I. PENJELASAN ARSITEKTUR & KEBIJAKAN HAK AKSES (2 TINGKAT)
--------------------------------------------------------------------------------
Sistem TokoMu menerapkan arsitektur otorisasi berbasis peran (Role-Based Access
Control / RBAC) yang terpusat dan konsisten di 3 lapisan pengamanan sistem:

1. Layer 1: Server-Side API Controller Guard (src/app/api/**/route.ts)
   Pengamanan rute backend menggunakan fungsi gatekeeper `requireRole(roles)`.
   Setiap HTTP request (GET, POST, PUT, PATCH, DELETE) yang masuk diverifikasi
   terlebih dahulu token sesi dan perannya sebelum mengeksekusi logika bisnis
   atau operasi database.

2. Layer 2: Route Page Guard (src/app/(dashboard)/**/page.tsx)
   Pengamanan level halaman pada Next.js Server Components. Halaman administratif
   yang sensitif secara langsung memanggil `requireRole()` saat rendering di
   server. Jika peran pengguna tidak diizinkan, server langsung mengembalikan
   status HTTP 403 (Forbidden) dan mengalihkan pengguna ke halaman penolakan.

3. Layer 3: Dynamic Sidebar & UI Mutation Guard (src/components/**)
   Pengamanan antarmuka pengguna di sisi client. Komponen navigasi (`app-shell.tsx`)
   dan formulir (`pengaturan-view.tsx`) membatasi visibilitas menu dan tombol
   simpan berdasarkan peran aktif pengguna untuk mencegah manipulasi visual.

--------------------------------------------------------------------------------
II. STRUKTUR DAN KLASIFIKASI PERAN (ROLES)
--------------------------------------------------------------------------------
Aplikasi memiliki 3 peran aktif yang dikelompokkan ke dalam 2 tingkat hak akses:

[TINGKAT 1: EKSEKUTIF / ADMINISTRATOR PENUH]
1. PIMPINAN (`pimpinan`)
   - Merupakan pemilik workspace (Workspace Owner) atau Super Admin warung.
   - Memiliki hak akses penuh (100%) ke seluruh modul operasional maupun modul
     administratif tingkat tinggi.
   - Eksklusif: Satu-satunya peran yang berhak mengelola karyawan, melihat audit
     log, mereset data workspace, mengatur jadwal shift, melihat Laporan PCM,
     dan mengubah konfigurasi/pengaturan warung.

[TINGKAT 2: STAF OPERASIONAL & KEUANGAN (SETINGKAT / IZIN SAMA)]
2. BENDAHARA (`pengelola_keuangan`)
   - Bertanggung jawab atas pengelolaan arus kas, buku hutang, investasi, bagi
     hasil, dan laporan operasional bulanan.
3. KASIR (`kasir`)
   - Bertanggung jawab atas transaksi kasir POS, inventaris, restok barang, dan
     pelayanan harian warung.

*Catatan Penting Tingkat 2:*
Peran BENDAHARA (`pengelola_keuangan`) dan KASIR (`kasir`) disetarakan dalam
hal izin operasional harian warung. Kedua peran ini DIBERIKAN AKSES PENUH ke
modul transaksi, inventaris, hutang, investor, bagi hasil, dan laporan bulanan,
tetapi SECARA EKSKLUSIF DILARANG mengakses modul administratif pimpinan.

1. Gatekeeper Utama RBAC:
   - Path: src/lib/server/rbac.ts
   - Bukti: Fungsi `requireRole(allowedRoles)` memvalidasi bahwa `user.role`
     harus berada dalam array `allowedRoles`. Jika tidak, melempar error `FORBIDDEN`.

     `await requireRole(["pimpinan"]);`

     `const canMutateSettings = role === "pimpinan";`
